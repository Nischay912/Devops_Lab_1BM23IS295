Q1: What is a Declarative Pipeline?
A: A Jenkins pipeline defined in a Jenkinsfile stored in the Git
   repository alongside code. It has a fixed structure with blocks:
   pipeline, agent, stages, steps, and post.
   This is called "Pipeline as Code."

Q2: What is the purpose of the Test stage?
A: It acts as a safety gate. pytest runs all unit tests automatically.
   If any test fails, Jenkins stops the pipeline immediately and the
   application is NEVER deployed. This prevents broken code from
   reaching production.

Q3: What is post-deployment verification (Stage 5)?
A: After starting the Flask server, we send a live HTTP GET request
   using curl to http://localhost:5050/ and assert:
   1. The HTTP status code equals 200
   2. The response body matches the expected text exactly
   This proves the deployed application is live and working correctly.

Q4: What does nohup do in Stage 4?
A: nohup (no hang-up) starts Flask as a background process that keeps
   running even after the shell that launched it closes.
   The & symbol runs it in the background so the pipeline can continue.

Q5: What is Pipeline as Code?
A: Storing the Jenkins pipeline definition in a Jenkinsfile in Git
   so the CI/CD process is version-controlled, reviewable, and
   reproducible across any machine.

Q6: What is the difference between Stage 2 Test and Stage 5 Test?
A: Stage 2 (Test): Tests the source code using unit tests with
   a fake test client. No real server is running.
   Stage 5 (Test Application): Tests the RUNNING deployed app by
   sending real HTTP requests using curl. Proves live deployment works.

Q7: Why pin versions in requirements.txt?
A: To ensure every build installs the exact same library versions.
   Without pinning, a newer version might introduce breaking changes
   and cause random failures in future builds.

Q8: What happens in the post always block?
A: It runs regardless of success or failure and kills any background
   Flask process using pkill. This prevents zombie processes from
   accumulating on the Jenkins agent between builds.
